# These aren't the relations you're looking for.

Imported documents are read the way their authors wrote them. A list item is prose, a footnote is a footnote and a file name with a wide space stays whole.

## Fixes

- A list item like `- See [Three](chapter-3.md)` was read as a relation of type "See". Converted documents are full of such lists, so the graph filled up with relation types nobody wrote. A relation written with a relative link now needs a lowercase type like `part_of` or a quoted phrase like `"relates to"`. Everything else is a plain link, which still counts in the graph.
- A list item that starts with a footnote reference, `- [^1] text`, was read as an observation with the category `^1`. It is a footnote again. Fluid no longer shows it as an observation either.
- A link to a file whose name holds a non-breaking space or a full-width space (U+3000, common in Japanese file names) was cut at that space, so `[Report](../日本　報告.md)` pointed at `../日本` and was reported broken. A link now ends only where CommonMark ends it: at a plain space or a control character. The same goes for attachments, for moves and for Fluid.
- A `[[name]]` inside a link's file name, like `[Doc](a[[x]]b.md)`, was read as a second link to `name`, and moving `name` rewrote the file name. It is now part of the file name and a move leaves it alone.

## Changes

- The relation rule above only applies to the relative link form, which is new in 0.29.0. `- See [[Three]]` is still a relation of type "See", as it always was.
- A capitalized relative-link bullet inside a callout no longer raises lint Q008, because it is not a relation any more.
- Crystalline reads each domain once more after the upgrade, so the graph picks up the fixes above. You don't have to do anything.

## Breaking changes

None.
